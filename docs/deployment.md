# Deployment guide (Supabase, Render, Brevo)

The hosted LIBRAS deployment runs on three free-tier services (see [ADR 0003](adr/0003-supabase-and-render-for-backend-auth-and-hosting.md)):

| Service | Role | Notes |
| --- | --- | --- |
| Supabase | PostgreSQL, Row-Level Security, Supabase Auth, and Storage | Identities and RLS policies live in the same database. |
| Render | API web service and static desk site (`render.yaml`, Singapore) | Node runs TypeScript directly with no build step. |
| Brevo | Transactional email over HTTPS API | Render's free web services block outbound SMTP ports (25, 465, 587), so `BrevoEmailSender` (`apps/api/src/email.ts`) sends over HTTPS. |

**Why Brevo.** Brevo's free plan (about 300 emails per day) verifies a single sender address and sends to any recipient without requiring DNS verification first. Mail sent from a free domain such as `gmail.com` may land in spam; use an institution domain when available and authenticate SPF and DKIM records for production delivery.

## Hosted commands

Hosted settings live in `.env.hosted` at the repository root (gitignored, separate from local `.env`). Every variable name is listed in `.env.example`.

| Command | Purpose |
| --- | --- |
| `npm run setup:hosted` | Runs the guided setup wizard (`scripts/setup-hosted.sh` via Git Bash on Windows) to configure Supabase, Brevo, Render, migrations, the Librarian account, GitHub secrets, and a test email. |
| `npm run db:migrate:hosted` | Lists pending migrations from `supabase/migrations/` and applies them after confirmation (`-- --dry-run` lists only; `-- --yes` skips the prompt). |
| `npm run seed:hosted` | Creates or updates the Librarian from `SEED_LIBRARIAN_EMAIL` and `SEED_LIBRARIAN_PASSWORD`, ensures Loan Policy and Pickup Window rows exist, and loads `data/library-catalog.xlsx` (or `-- --workbook <path>`). |
| `npm run labels:hosted -- --title "text" [--books 1] [--copies 3]` | Writes printable Code 128 Copy labels to `copy-labels.html` (85 x 36 mm, two per row on A4). Pass barcodes directly to print specific Copies. `npm run labels` targets the local database. |
| `npm run verify:hosted -- member \| search \| dispatch \| tier2 \| backdate \| cleanup` | Runs hosted verification checks and measurements (see [hosted-verification.md](hosted-verification.md)). |
| `npm run check:hosted` | Polls the hosted API `/health` endpoint (up to 5 minutes to allow Render wake-up). |
| `npm run email:test -- you@example.com` | Sends one test email through Brevo. |
| `npm run build:apk:hosted -w @libras/mobile` | Builds the release Android APK pointing at `EXPO_PUBLIC_API_URL`. |

## Environment variables

| Variable | Source | Needed on Render | Notes |
| --- | --- | --- | --- |
| `DATABASE_URL` | Supabase > Connect > Session pooler | Yes | Uses IPv4. Set `DATABASE_CA_CERT` to verify the Supabase TLS certificate. |
| `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` | Supabase > Project Settings > API Keys | Yes | Public project URL and publishable key. |
| `SUPABASE_SECRET_KEY` | Supabase > Project Settings > API Keys | Yes | Used by the API for Member sign-up confirmation and seeding. Never placed in mobile or web clients. |
| `BREVO_API_KEY`, `EMAIL_FROM_ADDRESS` | Brevo > SMTP & API, verified sender | Yes | Production refuses to start without both. |
| `TRUST_PROXY` | Set to `1` in `render.yaml` | Yes | Number of reverse proxies in front of Express so `req.ip` reflects the real client for sign-in rate limits. Unset locally. |
| `SWEEP_SECRET` | Generated by `npm run schedule:hosted` | Optional (required for scheduled sweeps) | At least 32 characters. |
| `CORS_ALLOWED_ORIGINS` | Desk site origin | Optional (required when `apps/web` is hosted) | Exact comma-separated origin list, for example `https://libras-desk.onrender.com`. No wildcards. |
| `EXPO_PUBLIC_API_URL` | Render API URL | No (build-time) | Read by `build:apk:hosted` and `check:hosted`. |

## Hosting the desk and phone scanner pages

`apps/web` builds two static HTML entry points: the Librarian desk at `/` and the phone scanner at `/scan.html`. Phone cameras require HTTPS (or `localhost`), which Render static sites provide automatically.

1. In Render, create or sync the `libras-desk` static site from `render.yaml` (`npm ci && npm run build -w @libras/web`, publish directory `apps/web/dist`).
2. Set `VITE_API_URL` to the hosted API base URL (no trailing slash) and deploy.
3. Set `CORS_ALLOWED_ORIGINS` on `libras-api` to the exact desk site origin and redeploy.
4. Open the desk URL, sign in as a Librarian, and pair the scanner phone using the 6-digit pairing code shown on screen.

For local phone testing over USB, forward ports with `adb reverse tcp:5173 tcp:5173` and `adb reverse tcp:3000 tcp:3000`, then open `http://localhost:5173/scan.html` on the phone.

## Operational notes

- **Rate limiting and proxies:** Failed sign-ins are capped at 5 per client address per 15 minutes (`AttemptLimiter`, held in API memory). Verify `req.ip` after deploying to confirm `TRUST_PROXY=1` matches Render's proxy depth. Supabase Auth also enforces its own rate limit per caller IP (default 30 sign-ins per 5 minutes).
- **Render free-tier sleep:** Free services sleep after 15 minutes of inactivity and take about a minute to wake. Any active scanner pairing lives in API memory and must be re-paired after a restart. Run `npm run check:hosted` before a live session.
- **Auto-deploy verification:** After merging to `main`, confirm in Render > Events that a deploy triggered and went live. If auto-deploy did not fire, verify Settings > Build & Deploy (`On Commit`, branch `main`) and GitHub repository permissions for Render.
- **Pickup Window expiry and Loan notices:** While awake, the API sweeps every minute. To keep sweeps running when Render sleeps (ADR 0007, ADR 0009), run `npm run schedule:hosted` after migrating to install the Supabase `pg_cron` and `pg_net` wake schedule, then add `SWEEP_SECRET` to `libras-api` on Render and run `npm run schedule:hosted` once more to verify.

## Step-by-step first-time setup

Run these commands from the repository root in Git Bash:

1. Ensure `render.yaml` is on `main` on GitHub and run `npm ci`.
2. Authenticate with `gh auth login` if you want the wizard to store GitHub repository secrets.
3. Run `npm run setup:hosted` and follow the eight interactive stages (local checks, Supabase project and keys, Brevo sender and API key, migrations and Librarian creation, Render Blueprint deploy, health and test email checks, GitHub secrets, and optional APK build).
4. If you skipped the APK step during the wizard, run `npm run build:apk:hosted -w @libras/mobile` later to produce `apps/mobile/build/libras.apk`.
5. Install on an Android device with `adb install -r apps/mobile/build/libras.apk`.
