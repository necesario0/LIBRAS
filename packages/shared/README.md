# @libras/shared

TypeScript shared by the API, the mobile app and the Librarian pages: API types, validation schemas and (once promoted from `benchmarks/`) the search module.

There is no build step. The package exports its TypeScript source (`src/index.ts`), so:

- relative imports use the `.ts` extension and type imports use `import type`;
- only syntax that can be erased is allowed (no enums, namespaces or parameter properties);
- code here must run in Node, React Native and the browser, so it must not import Node built-ins.

Pure-function tests go in `test/*.test.ts` and use Node's built-in test runner, like `benchmarks/test` (`npm test -w @libras/shared`).

- `barcode/code128.ts`: `encodeCode128C(digits)`, the bar and space widths of a Code 128 subset C barcode (the app draws them). Tested against bwip-js output.
- `digital-id.ts`: Digital ID constants, types and wording, `formatDigitalId`, `msUntilRefresh`.
- `scanner.ts`: the phone scanner's shared pieces: the pairing code schema, request bodies, the desk stream's event types and `SCANNER_MESSAGES`. `event-stream.ts`: `readEventStream`, a server-sent event reader for a `fetch` body (browsers' `EventSource` cannot send the Authorization header).
- `desk.ts`: what the desk shows about the Member at the desk, in a file of its own so Digital IDs, Loans and Fines can all use it: `DeskMember` (with `clearance`, which holds the unsettled Fines), `LoanStanding` and the desk session token schema.
- `scan.ts`: `readScan(raw)`, `isScanKey(key)` (a typed key that can be part of a scan), the whitelist and classification every desk scan goes through: a Digital ID (12 digits), or a Copy (its barcode or accession number).
- `loans.ts`: Loan and return types and wording (`LOAN_MESSAGES`, `RETURN_MESSAGES`), the desk session token schema and request bodies (`confirmLoanRequestSchema` `{ deskSession, copy }`, `endDeskSessionRequestSchema`; the `DeskSession` type and `DESK_SESSION_MINUTES` are in `digital-id.ts`, ADR 0008), `loanDueAt` (the end of the library day, UTC+8), `isLoanOverdue`, Renewals (`LoanRenewal`, `RENEWAL_REFUSALS`, `RENEWAL_REASONS` for My Loans, `RENEWAL_MESSAGES` for the API's refusals, `loanIdSchema`, `RenewLoanResponse`), `formatLibraryDate`, `formatLibraryDay`, `libraryDaysBetween`.
- `standing.ts`: Clearance and Good standing (ADR 0010). The API works them out, so the file is mostly types: `Clearance` (`cleared`, `loansOut`, `unsettledFines`), `ClearanceLoan`, `UnsettledFine`, `ClearanceResponse` (`GET /members/me/clearance`: `clearance` and `goodStanding`), and the Good standing reason codes `GOOD_STANDING_REFUSALS` (`overdue_loan`, `unsettled_fine`) with `GoodStanding`. The same codes are the error codes of a refused Loan, Hold or Renewal (the last two `RENEWAL_REFUSALS`). Their words come from one place per audience: `goodStandingNotice(reasons)` is the sentence the Member reads on Profile and on the Book page in place of Borrow and Place a Hold, and `GOOD_STANDING_MESSAGES` is the same sentence for one reason, which the API refuses a Hold with; `RENEWAL_REASONS` says it about renewing one Loan (My Loans, the due-tomorrow notice and a refused Renewal); `LOAN_MESSAGES.notInGoodStanding` says it to the Librarian at the desk. Also `totalOwedCentavos` (what the unsettled Fines add up to, used by the desk and the app).
- `plural.ts`: `plural(count, noun)` and `counted(count, noun)` ("1 day", "3 Loans"), the one way the app and the desk page pluralise a counted noun.
- `fines.ts`: `LoanFine` (a Loan's Fine: amount, days late, the rate and cap it was worked out with, and whether it is final, and its settlement), `FineSettlement`, the `settleFineRequestSchema` of `POST /desk/fines/settle`, `FINE_MESSAGES`, `SETTLE_AT_RETURN_MINUTES` and `formatPesos(centavos)` ("PHP 5", "PHP 2.50"). Every amount is whole centavos; the API computes every Fine.
- `announcements.ts`: Announcements: `announcementDetailsSchema` (what the desk page's form sends: title, body, link, first and last day, crop position), `Announcement` and the desk responses, `ANNOUNCEMENT_MESSAGES` (the API's refusals, which the desk page also shows before saving), `announcementOverlapMessage`, `isAnnouncementWebLink` and `announcementLinkSite` (https only; the button names the site), and the library-day helpers `libraryDayStart`, `libraryDayOf`, `nextLibraryDay` and `formatAnnouncementDay`.
- `push.ts`: push notifications: `PUSH_KINDS` (`holdReady`, `loanDueTomorrow`, `loanOverdue`, `announcement`), `PushSettings` and `pushSettingsChangeSchema`, `pushTokenSchema` (an Expo push token), `pushDeviceRequestSchema`, `signOutRequestSchema` (the optional `pushToken` of `POST /auth/sign-out`), `pushDestination(data)` (the screen a tapped push opens) and `PUSH_MESSAGES` (the Settings words).
- `members.ts`: the Member profile types and `memberFullName`, the name the app and the desk page write (first, middle, last).
- `password-reset.ts`: Forgot password request bodies (`requestPasswordResetSchema`, `checkPasswordResetCodeSchema`, `completePasswordResetSchema`, whose password is the sign-up `passwordSchema`), `PasswordResetRequestedResponse` and `PASSWORD_RESET_MESSAGES`.
- `password-change.ts`: `changePasswordSchema` (the body of `PUT /members/me/password`: the current password as typed, the new one held to `passwordSchema`), `ChangePasswordRequest` and `PASSWORD_CHANGE_MESSAGES`.
